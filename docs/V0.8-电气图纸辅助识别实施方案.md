## 一、阶段目标

把 V0.7 已有的“人工结构化录入图纸条件后逐回路核验”升级为“图纸辅助识别、人工确认、自动计算、证据可追溯”的闭环。

本阶段完成后，用户可导入一份电气 DWG、DXF 或 PDF，系统提取其中可识别的设备、线路、保护器和连接信息，生成候选回路。用户只需确认冲突和缺项，不再重复录入图纸中已经明确给出的事实；确认后的数据进入 V0.7 同一套确定性计算内核，输出页面、PDF 和 Excel 结果。

图纸识别结果只作为输入证据，不直接替代工程判断。任何低置信度推断、字段冲突或关键缺项均不得静默补全。

## 二、产品闭环

```text
DWG / DXF / PDF
        ↓
只读确定性提取（文字、图层、块、属性、坐标、页码）
        ↓
设备与拓扑候选（每项绑定原始证据）
        ↓
人工确认 / 驳回 / 补充缺项
        ↓
ConfirmedDrawingModel
        ↓
V0.7 CircuitNetworkInput 与确定性计算内核
        ↓
核验结果、缺项、依据、PDF / Excel
```

原始图纸默认只在本机读取，不上传网络。后续若接入云端模型，必须由用户明确启用，并在上传前提示文件范围和隐私影响。

## 三、纳入范围

### 3.1 文件接入与证据留存

- 支持 DWG、DXF 和可提取文字的 PDF；
- 忽略 BAK 及临时备份文件；
- 保存文件名、文件哈希、版面或页码、图层、块名、块属性、实体句柄、坐标范围及解析器版本；
- 原文件只读，任何提取、确认和计算均形成不可覆盖的修订版本；
- 图纸变化或确认结果变化后，旧计算结果自动标记为过期。

DWG 首选使用本机可用的只读 CAD 接口提取；无法直接解析时，允许用户导出 DXF 或 PDF 后继续。不得为完成解析而静默修改原图。

### 3.2 对象识别

仅识别 V0.7 计算内核已经支持的对象：

- 变压器及低压母线段；
- 低压馈线柜、配电箱和箱后分支；
- YJV 类电缆、BV/BVV 导线及现有目录覆盖的母线连接段；
- 断路器、MCB、MCCB、RCD；
- 普通三相负荷、单相照明负荷、直接启动电动机；
- 回路编号、设备编号、起点、终点及明确的“引自/至”关系。

### 3.3 拓扑候选

证据优先级固定为：

1. 图纸明确标注的“引自/至”关系；
2. 完全一致的设备或回路编号；
3. 块属性与可验证连接关系；
4. 名称、区域及空间邻近等弱证据。

弱证据只能形成待确认候选，不能自动建立正式连接。不同证据冲突时必须同时展示，不以置信度最高者静默覆盖其他证据。

### 3.4 人工确认页面

页面按回路展示：

- 已识别且无冲突的事实；
- 多个候选、参数冲突和来源位置；
- 计算所需但图纸中缺失的字段；
- 原图局部定位或实体证据；
- 每个字段的来源类型：`图纸`、`产品目录`、`规范/手册`、`系统推导`、`用户补充`、`参考假设`。

字段状态至少包括：`已提取`、`待确认`、`已确认`、`已驳回`、`冲突`、`缺失`。识别置信度不得等同于批准状态。

### 3.5 计算适配与成果

- 新增单向适配层：`ConfirmedDrawingModel → CircuitNetworkInput`；
- 不在图纸模块中复制负荷、电压降、短路、故障保护、热稳定或选择性公式；
- 同一冻结输入供网页、PDF 和 Excel 消费，导出时不得重新推导另一份结果；
- 识别证据、人工决定、计算输入、结果和依据形成完整审计链。

## 四、明确不纳入

- 任意类型 DWG 的全自动、零确认识别；
- 仅凭图形距离或系统图线长推断电气连接或实际电缆长度；
- 将 OCR 文本、模型猜测或相近产品参数直接当作图纸事实；
- 自动修改 DWG；
- 星三角、软启动、变频器等 V0.7 尚未支持的回路计算；
- 给排水、消防、暖通等多专业图纸审查；
- 云端多用户、多人协同和账号体系；
- 本阶段补齐全部厂家产品库。

## 五、核心数据边界

建议以最小必要模型实现，避免重建一套计算领域模型：

- `DrawingSource`：原文件身份、哈希、格式和解析版本；
- `DrawingEntityEvidence`：实体位置、文字、块、属性及原始值；
- `ExtractedFact`：规范化字段、原始证据、提取方式和置信度；
- `TopologyCandidate`：候选节点、边、支撑证据、冲突和缺项；
- `ConfirmationDecision`：用户确认、驳回、修订值、操作者和时间；
- `ConfirmedDrawingModel`：只含已确认事实的冻结网络；
- `DrawingImportRevision`：提取、确认、适配及计算结果的版本关联。

接口边界：

```text
extract_drawing(source) -> ExtractionBundle
interpret_electrical(bundle) -> CandidateNetwork
confirm_candidate(candidate, decisions) -> ConfirmedDrawingModel
build_network_input(confirmed) -> CircuitNetworkInput
```

语义识别通过可替换的 `DrawingInterpreter` 接口接入。首版必须具有不依赖云端模型的确定性规则回退路径；模型不可用时仍能提取证据、人工确认并完成计算。

## 六、实施批次

本版本按完整闭环组织开发，不把每一个字段拆成独立发布：

1. 建立文件、实体证据、候选、确认和修订数据模型；
2. 完成只读 DWG/DXF/PDF 提取及统一证据包；
3. 完成设备、参数和拓扑候选规则；
4. 完成图纸导入、冲突处理、缺项补充和人工确认页面；
5. 完成 `ConfirmedDrawingModel` 到 V0.7 计算输入的适配；
6. 接入项目保存、结果失效、PDF 和 Excel 证据输出；
7. 使用匿名夹具和本地真实图纸完成端到端浏览器验收；
8. 全量回归通过后一次收口，另行决定是否发布 `v0.8.0`。

## 七、验收标准

### 7.1 功能验收

- 图纸中已明确的事实无需用户重复录入；
- 每个识别值均可定位到文件、页码或 CAD 实体；
- 冲突和低置信度候选不会被静默确认为事实；
- 用户确认并补齐必要字段后，可进入现有完整回路计算；
- 上游三相干线、配电箱进线、箱后单相照明分支和直接启动电动机均按 V0.7 支持边界正确适配；
- 图纸或确认项变化后，旧计算结果明确过期；
- 网页、PDF 和 Excel 对同一修订输出一致。

### 7.2 测试验收

- V0.7 的 376 项既有测试全部通过；
- 增加 DWG/DXF/PDF 提取夹具测试；
- 增加证据定位、重复编号、跨图冲突、弱证据禁止自动确认测试；
- 增加确认、驳回、补充缺项和结果失效测试；
- 增加“导入图纸→确认回路→完整计算→保存→导出”的端到端测试；
- 真实工程资料只作本地验收，不进入 Git。

### 7.3 发布门槛

- 不以“能提取若干文字”视为完成；
- 至少一个照明链路和一个电动机链路完整跑通；
- 未确认事实不能进入正式计算输入；
- 所有公开测试夹具完成匿名化；
- 浏览器完成桌面宽度与窄屏可用性验收；
- 全量测试、源码编译检查、仓库隐私检查均通过。

## 八、多会话管理评估

本阶段采用一个主会话顺序开发，最多按需增加一个临时、只读审查任务，不建立 02、03、04 等长期并行会话。

原因：图纸证据模型、确认状态、计算适配和持久化高度串行，并会频繁修改同一组领域文件；长期拆分会重复加载大量项目背景，增加权限确认、接口错位、文件冲突和 Token 消耗。临时审查只适用于边界稳定、无需写入同一文件且能独立交付的工作，例如只读核对解析结果或发布前代码审计。

共享入口为本方案、`docs/当前任务.md`及最新阶段交接；主会话独占写入，临时审查任务只提交审查意见，不直接修改主会话正在编辑的文件。

退出条件：一旦出现反复授权、上下文重复读取、同文件冲突、接口反复返工，或并行收益不能明显覆盖协调成本，立即取消临时任务并恢复单会话顺序开发。

## 九、主要风险与控制

- DWG 解析依赖本机 CAD 能力：先做后端能力探测，并提供 DXF/PDF 回退；
- 图纸表达不统一：保存原始证据，规则只生成候选，不承诺零确认；
- OCR 或模型幻觉：未经人工确认不得进入冻结网络；
- 公式分叉：图纸模块只能调用 V0.7 公共内核；
- 私有资料泄露：真实图纸、规范、产品样本及其提取缓存继续排除在公开 Git 之外；
- 范围膨胀：发现 V0.7 不支持的回路类型时记录为后续项，不在识别模块中临时拼接新公式。

## 十、后续版本方向

- V0.9：补充正泰、德力西、施耐德等产品精确目录、曲线、I²t 和选择性证据，减少“无法判断”；
- V1.0：桌面安装包、离线运行、数据备份与恢复；
- 独立项目：电气、给排水、消防、暖通等安装专业图纸审查 Agent。该项目不得与 V0.8 混合开发，启动前另行冻结专业范围和协作模式。
