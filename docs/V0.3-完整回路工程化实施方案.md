# V0.3 完整回路工程化实施方案

日期：2026-08-11

## 1. 阶段目标

把现有“完整回路核验”的匿名验收夹具改造成用户可实际录入和复核的工作流。用户从变压器低压出口开始，逐段建立低压柜、配电线路、配电箱和末端负荷；系统复用同一网络数据完成计算，不要求重复填写可推导参数。

V0.3必须同时支持两种任务：

1. 快速设计：用户给出最少已知条件，系统形成电缆及保护器件参数候选；
2. 既有设计核验：用户录入图纸已有电缆、断路器和线路条件，系统逐项判断原设计，不用替代候选掩盖原设计结论。

## 2. 本阶段完整链路

```text
上级系统
→ 10/0.4kV变压器
→ 低压进线/馈线柜
→ 一级配电线路
→ 下级配电箱
→ 末端线路
→ 普通负荷或V0.2电动机负荷
```

每个节点和线路段均保留输入来源、推导过程、结果状态和警告。

## 3. 用户必须提供的最少条件

### 电源

- 变压器容量；
- 变压器铭牌`uk%`，图纸没有时允许从已核实同类表中选择参考值并明确标记；
- 变压器低压额定电压；
- 上级系统短路容量；不知道时可采用已经确认的100MVA参考工况，但不得冒充现场实测值。

### 每段线路

- 起点和终点；
- 长度；
- 敷设方式；
- 新设计时选择导体系列，既有核验时填写原电缆规格；
- 环境温度、成组数量等未知时采用页面明确显示的参考工况，正式状态保持有条件或无法判断。

### 负荷

- 普通负荷：kW、kVA或已知电流；
- 电动机：V0.2已有的目录功率或铭牌数据；
- 配电箱/干线：只有在确需负荷汇总时才填写需要系数、同时系数，不把末端单回路复杂化。

## 4. 系统自动取得或推导的数据

- 变压器额定电流及等值R/X；
- 上级系统等值阻抗；
- 各节点累计电源阻抗；
- 上下游负荷流和各段设计电流；
- 电缆载流量、温度及成组修正；
- 电缆R/X和累计电压降；
- 各节点最大三相短路、最小相—N短路和TN相—PE故障电流；
- 相导体及PE热稳定允许条件；
- PE最小截面；
- 断路器额定电流、壳架、额定电压、分断能力及可用整定约束；
- 下游参数变化后的结果失效范围。

用户已经给出的原设备参数只用于核验，不被系统推荐值覆盖。

## 5. 计算闭环

每段线路按同一顺序执行：

```text
负荷流
→ 设计电流
→ 保护器参数约束
→ 电缆载流量候选
→ 电压降复核
→ 节点短路及接地故障
→ 电缆相线/PE热稳定
→ 分断能力及自动切断
→ 上下级配合证据
→ 收敛为主方案或明确无法判断原因
```

电压降和热稳定是电缆截面的复核条件，不作为与电缆选型分离的孤立结果。断路器也必须同时满足负荷、导体保护、短路分断和故障切除条件后才形成主方案。

## 6. 页面结构

### 第一步：建立电源

以普通用户能看懂的字段录入变压器和上级系统。专业等值参数放在“计算过程”中，不要求用户填写。

### 第二步：绘制放射式回路

用户按顺序增加“线路段”和“节点”。首版只允许单电源放射式结构，暂不提供环网、母联并列和多电源自动切换。

### 第三步：选择任务

- 新设计：选择导体系列和负荷，系统求主方案；
- 图纸核验：录入原电缆和原断路器，系统输出原设计通过/不通过/无法判断，并另列替代候选。

### 第四步：查看结果

先显示整条回路总览，再允许展开每段的输入、公式代入、来源、警告和未闭合项。用户不需要在多个规格中自行猜选。

## 7. 数据模型改造

复用现有完整回路引擎，新增工程化输入层：

- `CircuitNetworkInput`：整条放射式网络；
- `PowerSourceInput`：上级系统和变压器；
- `CircuitNodeInput`：低压柜、配电箱、设备节点；
- `FeederSegmentInput`：每段电缆和保护器；
- `LoadInput`：普通负荷或电动机负荷；
- `ExistingDesignInput`：图纸已有器件参数；
- `NetworkOutcome`：总览、逐段结果、主方案、原设计结论和未闭合项。

页面、数据库和计算书只消费结构化结果，不在模板中重复计算。

## 8. 验收样例

建立一个不含真实工程名称的匿名完整案例：

```text
100MVA上级系统
→ SCB11 10/0.4kV变压器
→ 低压馈线柜
→ 一级配电箱
→ 二级配电箱
→ 普通负荷与一台直接启动电动机
```

案例必须完成：

- 新设计主方案计算；
- 已有电缆和断路器核验；
- 任一上游参数变化后的全链路重算；
- 任一下游负荷变化后的受影响段重算；
- 页面值、引擎值和测试断言一致；
- 缺少现场数据时只显示明确的参考工况和未闭合项。

## 9. 本阶段不纳入

- DWG自动识别和跨图纸拓扑拼接；
- 环网、母联并列、多台变压器并列和发电机切换；
- 星—三角、软启动、变频及多电动机群；
- 自动生成施工图或采购订单；
- Excel批量导入、PDF正式计算书和多人协作。

这些能力只有在完整回路人工录入闭环稳定后再增加。

## 10. 开发顺序

1. 固化输入/推导/查表三类字段矩阵；
2. 建立工程化网络输入模型及统一校验；
3. 接入现有完整回路引擎和V0.2电动机负荷；
4. 完成放射式回路编辑页面；
5. 完成新设计与既有核验两种结果视图；
6. 建立匿名完整案例和端到端回归测试；
7. 完成公开文件边界检查后发布V0.3.0。

## 11. 多会话管理评估

本阶段不采用多个长期开发会话。

原因：输入模型、网络拓扑、计算链和页面高度串行，并会频繁修改同一组核心文件；拆分会重复读取大量上下文，增加接口错位、文件冲突、权限确认和Token消耗。当前采用“单主会话顺序开发＋必要时一次临时只读审查＋精简交接文档”。

只有当计算引擎接口已经冻结，且页面、导出或独立资料核验能够在不修改核心模型的条件下单独交付时，才考虑临时并行任务。出现重复授权、上下文重复或文件冲突时立即停止并行。

## 12. 开始编码前的确认点

- 本方案是否同意以“人工建立放射式完整回路”为V0.3核心，而不先做DWG自动识别；
- V0.3是否只保存一个当前工作回路，还是同步恢复项目历史和多版本记录；
- 当前默认100MVA上级系统参考工况是否继续保留。

确认结果（2026-08-11）：采用人工建立放射式完整回路；V0.3只维护一个当前工作回路，不恢复项目历史；保留明确标注的100MVA上级系统参考工况。已据此开始实施。
